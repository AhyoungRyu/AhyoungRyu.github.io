# 홈 중심 이력서 정보 구조 개선 설계

## 목표

채용 담당자가 상세 페이지를 열지 않아도 홈 화면에서 경력, 대표 프로젝트, 기술 스택, 구체적인 역할과 결과를 파악할 수 있게 한다. 데스크톱에서는 첫 화면 이후 한두 번의 긴 스크롤로 전체 윤곽을 훑을 수 있는 밀도를 유지한다.

## 현재 문제

- 경력 영역은 회사별 설명과 성과가 홈에 노출되어 있다.
- 주요 프로젝트 영역은 프로젝트 설명과 기술 스택만 보여준다.
- 구체적으로 무엇을 했고 어떤 결과가 있었는지는 `자세히 보기`를 눌러야 확인할 수 있다.
- 상세 페이지 링크가 시각적으로 강조되어 핵심 정보보다 클릭 행동을 먼저 요구한다.
- 웹 화면의 섹션 여백과 프로젝트 행 여백이 인쇄본보다 넓어 전체 내용에 비해 스크롤이 길다.

## 검토한 접근

### 1. 프로젝트 전문을 홈에 모두 펼치기

문제, 기여, 결과를 모두 보여줄 수 있지만 프로젝트 다섯 개만으로 화면이 지나치게 길어진다. 핵심 판단보다 서술량이 많아져 빠른 검토에 불리하다.

### 2. 프로젝트마다 역할과 결과를 한 줄씩 노출하기

현재 요약 아래에 두 개의 짧은 근거를 추가한다. 첫 줄은 직접 한 일, 둘째 줄은 결과를 보여준다. 정보량과 스캔 속도의 균형이 가장 좋다.

### 3. 프로젝트를 2열 카드로 바꾸기

전체 높이는 줄지만 문장 폭이 좁아지고 회사, 기간, 이미지, 기술 스택의 정렬이 불규칙해진다. 일반적인 이력서 읽기 흐름과도 멀어진다.

## 선택한 설계

두 번째 접근을 사용한다.

- 5개 대표 프로젝트를 그대로 유지한다.
- 각 프로젝트에 `내가 한 일`과 `결과`에 해당하는 두 문장을 추가한다.
- 문장은 기존 한국어 최신 원본의 `contributions`와 `outcomes`에서 선택하거나 의미를 보존해 압축한다.
- 한국어는 짧은 서술형으로 쓰되 이력서 본문과 어울리는 자연스러운 문장으로 유지한다.
- 영어는 한국어와 같은 사실을 전달한다.
- 별도의 `자세히 보기` 링크 문구는 제거한다.
- 프로젝트 제목과 썸네일 링크는 남긴다. 링크는 추가 자료를 원하는 사람을 위한 보조 수단이다.
- 기술 스택은 현재처럼 각 프로젝트 바로 아래에 둔다.
- 전체 경력 아카이브 링크는 유지한다. 홈에 없는 과거 세부 기록을 위한 보조 자료임을 분명하게 표시한다.

## 홈에 노출할 프로젝트 근거

### AI Agent Messenger SDK

- 고객 환경에서 검증 가능한 React SDK API와 컴포넌트 구조를 설계하고 고도화함.
- 초기 PoC와 실제 사용자 A/B 테스트를 지원해 제품 피드백 주기를 단축함.

### Chat UIKit 레거시 현대화

- 5년간 누적된 React 구조를 재설계하고 테스트 전략을 수립함.
- 테스트 커버리지를 22.51%에서 50%로 높이고 고객 이슈를 약 30% 줄임.

### 토스뱅크 개인대출 퍼널

- 웹과 앱 간 프로토콜, 웹 스크래핑 통신, 모바일 E2E 환경을 구축함.
- 토스뱅크 오픈에 맞춰 개인대출 신청과 관리 경험을 출시하고 운영함.

### 디지털 병리 Annotation & Visualization

- 기술 스택과 구조를 결정하고 기존 도구를 한 달 반 만에 재개발함.
- Web Worker와 OffscreenCanvas로 대형 병리 이미지의 AI 결과 시각화를 구현함.

### Zepl 노트북·시각화 성능 개선

- Web Worker 데이터 파이프라인과 Canvas 기반 Nivo 차트 7종을 도입함.
- 주요 상호작용 속도를 100~300% 개선하고 대형 그래프의 페이지 멈춤을 해결함.

## 밀도 조정

- 프로젝트 행의 상하 여백을 줄인다.
- 회사 경력 영역은 프로젝트와 중복되는 성과를 두 개에서 한 개로 줄인다. 회사, 역할, 요약, 대표 근거 하나, 기술 스택은 모두 유지한다.
- 프로젝트 설명과 근거 목록 사이의 간격을 작게 유지한다.
- 근거 목록은 프로젝트당 두 줄로 제한한다.
- 데스크톱 썸네일은 현재보다 약간 작게 조정한다.
- 모바일에서는 이미지가 본문 뒤에 오도록 유지하고 터치 가능한 제목 링크를 제공한다.
- 인쇄본에서는 두 근거를 모두 보여주되 2페이지 구성을 유지한다.

## 접근성과 링크

- 제목 링크는 프로젝트명을 그대로 접근 가능한 이름으로 사용한다.
- 썸네일 링크의 접근 가능한 이름에는 프로젝트명과 `프로젝트 기록 보기`를 사용한다.
- 의미 없는 화살표와 독립적인 CTA 문구는 제거한다.
- 링크를 누르지 않아도 동일한 핵심 사실을 읽을 수 있어야 한다.

## 검증 기준

- 홈에 프로젝트 행이 5개 표시된다.
- 각 프로젝트에 근거 문장 2개가 표시된다.
- 홈에 `자세히 보기`와 `Read details` 문구가 없다.
- 모든 프로젝트 제목과 썸네일은 기존 상세 페이지로 연결된다.
- 한국어와 영어의 프로젝트 순서와 사실이 일치한다.
- 한국어와 영어 PDF는 각각 2페이지를 유지한다.
- PDF마다 기존 이미지 11개가 유지된다.
- 공개 데스크톱 화면에서 홈의 전체 높이가 기존보다 과도하게 늘지 않는다.
- 1440×1000 화면에서 첫 화면 이후 약 두 번의 화면 단위 스크롤로 끝까지 도달할 수 있다.
